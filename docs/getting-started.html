DocR3V — Getting started

Comparing two versions of a document, word by word. Written for reviewers, not for IT.

DocR3V takes two versions of the same document and shows you exactly which words changed. Not "this paragraph was replaced" — the individual words. A job title that became a different job title, a temperature that moved by two degrees, a "must" that became a "should".

There is nothing to buy, nothing to license, and no account to create. This guide takes about ten minutes to follow once.

Your documents stay on your computer. DocR3V does the comparison inside your web browser, on your own machine. The documents you open are never uploaded, never sent anywhere, and never stored on anyone else's computer. This is not a policy promise — the application is built so that the browser itself blocks it from contacting the internet at all. You can compare confidential documents on a machine with its network cable unplugged, and everything works.

  1. Open your web browser — Chrome, Edge, Firefox or Safari all work.
  2. Go to the address below.

Add it to your Start menu or dock (optional, 5 seconds). This does not install software in the usual sense — nothing is added to your computer's programs list and no administrator permission is asked for. Step 3 — Option B: download the offline file

This gives you one file, roughly 400 KB, that contains the whole application. Put it on a network drive, email it to a colleague, or keep it in a validation folder — wherever it goes, double-clicking it opens a working copy of DocR3V.

https://github.com/OpenGxPTools/DocR3V/releases/latest

  1. Go to the address above.
  2. You will see a page describing the newest version. Scroll down to the heading Assets. It is a short list of files.
  3. Click the file named DocR3V-1.0.0.html (the numbers will be higher in newer versions). Your browser downloads it.
  4. The file lands in your Downloads folder. Move it somewhere you will find it again — your Documents folder, or your desktop.
  5. Double-click it. It opens in your web browser and DocR3V is ready to use.

Ignore the other files under Assets. "Source code (zip)" and "Source code (tar.gz)" are for developers and will not do anything useful for you. The file ending in .sha256 is a fingerprint used for record-keeping — see the last section.

If your browser warns you about the download. Some browsers show a caution such as "This type of file can harm your computer" for anything downloaded, including ordinary documents. Choose Keep. If you would like to confirm the file is genuine before opening it, the release page publishes its fingerprint — the last section of this guide explains how to check it.

To give it a proper icon. Right-click the file, choose Send to ▸ Desktop (create shortcut) on Windows, or drag it to your dock on a Mac. From then on it behaves like any other application icon.

Step 4 — Compare two documents

However you opened DocR3V, using it is the same.

  1. Choose the original. Click the first box, labelled Original, and pick the earlier version of your document. You can also drag the file onto the box.
  2. Choose the revised version. Do the same in the second box, labelled Revised.
  3. Click Compare.

Word documents (.docx), OpenDocument files (.odt), Markdown (.md) and plain text (.txt) can all be compared, up to 5 MB each. PDFs cannot — save the document as Word or OpenDocument first.

Reading the result

The two versions appear side by side, with the changes marked:

What you see What it means
struck through, red Text that was in the original and has been removed
shaded, green Text that is new in the revised version
A small ◇ marker The words did not change, but their formatting did — bold added, for instance

Along the top you will find a count of the changes, buttons to move to the next and previous change, a Merged view that shows both versions in a single column, and a Changes only tick box that hides every paragraph that stayed the same.

Know what is not checked. The What is checked button lists exactly which kinds of change DocR3V looks for and which it does not. It is worth reading once. Font sizes, colours and page layout are not compared — so if nothing is reported, that means no change of the kinds listed, not "no change at all".

Keeping the result

Button What you get
Download HTML A self-contained report you can email, archive or open later
Download ODT (tracked) A Writer document with real tracked changes, so you can accept or reject each one
Print / PDF Your browser's print window — choose "Save as PDF" for a paginated, signable copy
Copy redline The marked-up text on your clipboard, ready to paste into Writer or Word

Every report carries the DocR3V version that produced it. That matters if a comparison is ever filed: the version identifies exactly which build made it.

If something goes wrong

What you see What to do
Double-clicking the downloaded file opens a text editor full of code Right-click it, choose Open with, and pick your web browser. Tick "always use this" if offered.
The page is blank or nothing happens when you click Compare Your browser may be an old version. Chrome, Edge, Firefox and Safari from the last two years or so all work; Internet Explorer does not.
"This file is too large" The limit is 5 MB per document. A document that big is usually carrying large images; a copy with the images removed will compare fine, since images are not compared anyway.
"This document could not be read" The file may be damaged, password-protected, or not really the format its name claims. Open it in Word or Writer and save a fresh copy.
Your workplace blocks the website Use Option B. The downloaded file needs no internet connection and no access to any website.
The comparison looks wrong or misses something Check the What is checked list first — it may be a kind of change DocR3V deliberately does not report.

For quality and validation records

If a comparison is being filed as evidence, use Option B and keep the downloaded file with the record. The reason is reproducibility: the browser version updates itself over time, whereas the downloaded file is fixed forever at the version it was built as, and will produce the same comparison in five years as it does today.

Each release publishes a SHA-256 fingerprint — a long string of letters and numbers, unique to that exact file. It lets anyone confirm that an archived copy is byte-for-byte the file that was published. To check a copy you hold, on Windows open Command Prompt and run:

certutil -hashfile DocR3V-1.0.0.html SHA256

On macOS or Linux, open Terminal and run:

shasum -a 256 DocR3V-1.0.0.html

The result should match the fingerprint on the release page exactly. If it does not, download the file again.

DocR3V has not been validated for regulated use. It is a review aid: it shows a reviewer where to look. Whether its output can support a GMP decision is a question for your own validation process, and this guide is not an answer to it.
